# jp-law-mcp

![code: Apache-2.0](https://img.shields.io/badge/code-Apache--2.0-blue) ![data: CC BY 4.0](https://img.shields.io/badge/data-CC--BY--4.0-green)

日本の行政実務者が Claude などの AI から使える、法令と国会会議録の MCP サーバーです。
条文の取得（時点指定）、改正履歴・新旧比較、本文検索、**AI が書いた文書の法令引用の実在確認**、**引用・委任の逆引き**、国会会議録の発言検索ができます。
韓国の [korean-law-mcp](https://github.com/chrisryugj/korean-law-mcp) にならい、データは [JLaw-CiteGraph（jlawcite）](https://github.com/yabooung/jp-law-citation-graph) を使います。

## 使い方

試験公開中の接続先（Streamable HTTP、インストール不要）:

```
https://jp-law-mcp.vercel.app/mcp
```

- **Claude（claude.ai・デスクトップ）**: 設定 → コネクタ → カスタムコネクタを追加 で上の URL を入れる
- **Claude Code**: `claude mcp add --transport http jp-law https://jp-law-mcp.vercel.app/mcp`
- **自分の PC で動かす**（stdio）:
  ```bash
  git clone https://github.com/yabooung/jp-law-mcp && cd jp-law-mcp
  npm install && npm run build
  claude mcp add jp-law -- node "$(pwd)/build/index.js"
  ```

試験公開の接続先は、外部 API への負担を抑えるため送信元ごとに毎分 60 件までです。

### 例

> 行政手続法第8条（理由の提示）は 2018 年 4 月 1 日時点と現在で違いがあるか。この条を引用している法令と、関連する国会での発言も教えて

AI が `compare_article`・`find_citing_provisions`・`search_diet_records` を使い、原文リンク付きで答えます。

> 部下の通知文案「本件申請は、行政手続法第8条第3項及び地方税法第999条の規定に基づき不許可とします」の法令引用を確認して

`verify_citations` が、第8条は第2項までであること、地方税法に第999条がないことを知らせます。

## ツール

| ツール | 内容 | データ源 |
|---|---|---|
| `find_law` | 法令名・略称から法令ID・種別・現行/廃止を調べる | [e-Gov 法令API v2](https://laws.e-gov.go.jp/api/2/swagger-ui/) |
| `get_article` | 条文を読む。`asof` でその日に施行されていた版（行為時法）。現行なら施行予定の改正を警告 | 同上 |
| `law_history` | 改正履歴（施行日・改正法令・現行/過去/未施行） | 同上 |
| `compare_article` | 同じ条の二つの時点の新旧比較 | 同上 |
| `search_law_text` | 本文の全文検索（空白区切り AND）。上位 3 法令はその文が第何条かも示す | e-Gov 法令API v2 `/keyword`・本文 |
| `verify_citations` | 文章中の法令引用を取り出し、法令・条・項・号の実在を確認。存在しない条・項、法令番号と名称の食い違い、架空の法令名、廃止法令を知らせ、照合用の抜粋を付ける（[評価](#引用確認の評価)） | `data/structure.json.gz`・`data/law_names.json.gz` + e-Gov（1 回最大 10 件） |
| `find_citing_provisions` | **逆引き**: この条（または法令全体）を引用・委任元として参照している条文を法令ごとに。`depth=2` で間接的な影響範囲 | `data/graph.json.gz`（jlawcite から生成） |
| `find_cited_provisions` | この条が引用している条・委任先の政令省令 | 同上 |
| `search_diet_records` | 国会会議録の発言検索（立法趣旨・政府答弁の確認） | [国会会議録検索システム 検索用API](https://kokkai.ndl.go.jp/api.html) |

未対応: 附則・別表の中身、判例・通達・条例、法令の意味検索（予定）。

## 引用確認のしくみ（verify_citations）

1. 文章から「第N条」を探し、直前の法令名を辞書（`data/law_names.json.gz`: 正式名 8,998・略称 3,167・別称 158・旧題名 738・法令番号 8,645）で決める。辞書の名前の直前に漢字が続く場合（「地方行政手続法」）は辞書の名前に読み替えず「該当なし」とする
2. 「所得税法第33条、第34条」のような並びは直前の引用の法令を引き継ぐ（直前の法令が分からなければ分からないことも引き継ぐ）。文章の中の略称の定め（「以下「法」という。」）、「同法」「同令」、「旧」「改正前の」（現行版では確かめない）、附則（確かめない）も読む
3. 条・項・号の有無を `data/structure.json.gz`（e-Gov スナップショット 2026-09-27 の 8,998 法令・243,277 条の形、0.9MB）で判定する
4. e-Gov API には 1 回の確認で最大 10 件だけ問い合わせる。スナップショットで「ない」と出たものを先に現行版で確かめ直し（スナップショット後の改正）、残りで「ある」ものの抜粋を取る。API が答えればそちらを優先し、答えなければスナップショットの判定を日付付きで返す

確かめるのは法令・条・項・号の実在だけで、引用した主張が条文に合っているかは判断しません。

## 引用確認の評価

国税庁「質疑応答事例」の関係法令欄と、それを条に結び付けた正解（jlawcite の `eval/v2/nta_gold.jsonl`。このツールとは別のコードで作成）で測りました。事例を id のハッシュで dev 591 件・test 595 件に分け、dev だけを見て直し、test は設定を決めたあと 1 回だけ実行しました（2026-10-20）。e-Gov API は呼ばず、同梱スナップショットでの判定を測っています。数値は `eval/results/`。

| | dev | **test** |
|---|---|---|
| 正解の条を取り出せた割合 | 99.9%（1,262/1,263） | **99.8%（1,258/1,261）** |
| 正しい引用に警告を出した割合 | 0.12%（1/843） | **0.68%（6/878）** |
| 入れた誤り（存在しない条・項、架空の法令名、法令番号の食い違い）を見つけた割合 | 100%（1,460/1,460） | **100%（1,479/1,479）** |

test で警告した 6 件はすべて租税特別措置法施行令・同施行規則の項・号です。該当ページは「令和7年8月1日現在の法令・通達等に基づいて作成」で、スナップショット（2026-09-27）とのあいだの改正で項番号がずれたものと見ています（推定）。古い資料の引用は `asof` で当時の版を指定して確かめてください。

限界: 税務の資料だけで測っています。関係法令欄は整った書き方で、文の中に混ざった引用では法令名なし（ℹ）が増えます（回答本文で 13.6%）。誤りを入れる試験は条・項の有無をスナップショットで作っているので、確かめているのは「誤った引用を正しい法令・条に結び付けて判定に回せるか」です。

## 引用グラフ（data/graph.json.gz）

- `scripts/export_graph.py` が jlawcite の検索DBから作る。e-Gov スナップショット 2026-09-27、本則の条から出る引用・委任 526,505 組（条→条）と 26,228 組（条→法令）、198,097 条、gzip 2.5MB
- 附則から出る参照と同じ条の中の参照は入れていない
- 「行政手続法第二章（申請に対する処分）（第八条（理由の提示）を除く。）」のような、他の法令の章・節・款のあとの括弧の中の条は、その法令の条として扱う（2026-10-20 の jlawcite 2.5.0 の抽出修正で作り直したもの。それまでは引用元の法令自身の第八条に結び付いていた。全体で 962 組を追加・387 組を削除、無作為 20 件を本文と照合して全件正しい）
- 読み込みは最初に使ったときだけ（約 0.2 秒、ヒープ約 51MB）

## データ源の利用条件（2026-10-19 確認）

- **e-Gov 法令API v2**: 時点指定（`asof`）は 2017-04-01 以降のみ（それより前は API がエラー 400044）。法令は著作権法第13条で権利の目的とならない。出典「e-Gov 法令検索（デジタル庁）」を付ける
- **国会会議録 API**: 手続不要。多重リクエスト禁止、取得し終えてから数秒空ける、1 回 100 件まで、短時間での大量アクセスは遠慮。発言の著作権は発言者にあるが、公開の政治上の演説・陳述は著作権法第40条で利用可（同一著作者のものの編集は除く）。結果は抜粋とリンクだけを返す
- 外部 API への負担を抑えるための決まりは [CONTRIBUTING.md](CONTRIBUTING.md)（回数制限は公開されていないが、2026-10-20 に毎秒約 4 件を 40 秒送ったところで一時的に止められた）

## 開発

```bash
npm install
npm test            # 単体テスト（実 API は呼ばない）
npm run build
LIVE=1 npx vitest run test/live   # 実 API に数件だけ問い合わせる（手で実行するときだけ）
node eval/verify_eval.mjs --gold <jlawcite の eval/v2/nta_gold.jsonl> --split dev   # 引用確認の評価（API は呼ばない）
python scripts/export_structure.py --nodes <jlawcite のパイプライン出力 jp_nodes.jsonl> --snapshot <日付>   # スナップショット更新
```
