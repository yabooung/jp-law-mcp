# jp-law-mcp

![code: Apache-2.0](https://img.shields.io/badge/code-Apache--2.0-blue) ![data: CC BY 4.0](https://img.shields.io/badge/data-CC--BY--4.0-green)

日本の行政実務者が Claude などの AI から使える、法令と国会会議録の MCP サーバーです。
条文の取得（時点指定）、改正履歴・新旧比較、本文検索、**AI が書いた文書の法令引用の実在確認**、**引用・委任の逆引き**、国会会議録の発言検索ができます。
確かめるのは国の法令（法律・政令・府省令など）の条・項・号の実在です。通達・判例・条例の引用は、見つけて「確かめていない」と示します。
引用グラフ・法令名・条文の形のデータは [JLaw-CiteGraph（jlawcite）](https://github.com/yabooung/jp-law-citation-graph) から作っています。

## 使い方

試験公開中の接続先（Streamable HTTP、インストール不要）:

```
https://jp-law-mcp.vercel.app/mcp
```

- **Claude（claude.ai・デスクトップ）**: 設定 → コネクタ → カスタムコネクタを追加 で上の URL を入れる
- **Claude Code**: `claude mcp add --transport http jp-law https://jp-law-mcp.vercel.app/mcp`
- **自分の PC で動かす**（stdio、Node.js 20 以降）: `npx -y jp-law-mcp`
  - Claude Code: `claude mcp add jp-law -- npx -y jp-law-mcp`
  - Claude デスクトップなど（設定ファイル）: `{"mcpServers": {"jp-law": {"command": "npx", "args": ["-y", "jp-law-mcp"]}}}`
  - Claude デスクトップの拡張: [Releases](https://github.com/yabooung/jp-law-mcp/releases) の `jp-law-mcp-<版>.mcpb` を開く（macOS・Windows 版の Claude デスクトップは Node.js を内蔵しているので、別に入れなくてよい）
  - 外部 API へは自分の回線から問い合わせるので、試験公開の接続先の回数制限を受けません。たくさん使う場合はこちらを勧めます

試験公開の接続先は、外部 API への負担を抑えるため、ツールの呼び出しを利用者ごとに毎分 60 件までにしています（接続の手続きは数えません）。利用者は送信元 IP で分けます。
組織のプロキシや AI サービスの中継のように多くの人が同じ送信元になる場合は、接続 URL に `?u=` と任意の文字列
（英数字・`_`・`-`、64 字まで。例 `https://jp-law-mcp.vercel.app/mcp?u=tanaka-01`）を付けると、その文字列ごとに数えます
（同じ送信元の合計は毎分 600 件まで）。認証ではないので、他人に知られても困らない文字列にしてください。

### 例

> 行政手続法第8条（理由の提示）は 2018 年 4 月 1 日時点と現在で違いがあるか。この条を引用している法令と、関連する国会での発言も教えて

AI が `compare_article`・`find_citing_provisions`・`search_diet_records` を使い、原文リンク付きで答えます。

> 部下の通知文案「本件申請は、行政手続法第8条第3項及び地方税法第999条の規定に基づき不許可とします」の法令引用を確認して

`verify_citations` が、第8条は第2項までであること、地方税法に第999条がないことを知らせます。

### よく使う手順（プロンプト）

クライアントのプロンプト一覧（Claude なら「＋」や「/」のメニュー）から選べます。

| プロンプト | 内容 |
|---|---|
| `check_document` | 通知文・答弁案・AI の回答などの法令引用を確かめ、直すべき箇所と直し方を一覧にする |
| `article_at_date` | 処分・申請の日に施行されていた条文（行為時法）と、その後の改正を確かめる |
| `amendment_impact` | ある条を改正するとき、引用・準用している他の法令の条を洗い出す |

接続した AI には、法令を挙げて答えるときは答えを返す前に `verify_citations` で確かめ、条文の中身は `get_article` で原文を読んでから書くよう、サーバーから伝えています。

## ツール

| ツール | 内容 | データ源 |
|---|---|---|
| `find_law` | 法令名・略称から法令ID・種別・現行/廃止を調べる。旧題名・施行予定の改正後の題名なら、いまの法令を示す | [e-Gov 法令API v2](https://laws.e-gov.go.jp/api/2/swagger-ui/) |
| `get_article` | 条文を読む。`asof` でその日に施行されていた版（行為時法）。現行なら施行予定の改正を警告 | 同上 |
| `law_history` | 改正履歴（施行日・改正法令・現行/過去/未施行） | 同上 |
| `compare_article` | 同じ条の二つの時点の新旧比較 | 同上 |
| `search_law_text` | 本文の全文検索（空白区切り AND）。上位 3 法令はその文が第何条かも示す | e-Gov 法令API v2 `/keyword`・本文 |
| `verify_citations` | 文章中の法令引用を取り出し、法令・条・項・号の実在を確認。存在しない条・項、法令番号と名称の食い違い、架空の法令名、廃止法令を知らせ、照合用の抜粋を付ける（[評価](#引用確認の評価)） | `data/structure.json.gz`・`data/law_names.json.gz` + e-Gov（1 回最大 10 件） |
| `find_citing_provisions` | **逆引き**: この条（または法令全体）を引用・委任元として参照している条文を法令ごとに。`depth=2` で間接的な影響範囲 | `data/graph.json.gz`（jlawcite から生成） |
| `find_cited_provisions` | この条が引用している条・委任先の政令省令 | 同上 |
| `search_diet_records` | 国会会議録の発言検索（立法趣旨・政府答弁の確認） | [国会会議録検索システム 検索用API](https://kokkai.ndl.go.jp/api.html) |

未対応: 附則・別表の中身の確認、判例・通達・条例の実在確認（引用は見つけて「確かめていない」と示す）、法令の意味検索。

## 引用確認のしくみ（verify_citations）

1. 文章から「第N条」を探し、直前の法令名を辞書（`data/law_names.json.gz`: 正式名 <!--v:names.canonical-->8,981<!--/v-->・略称 <!--v:names.abbrev-->3,165<!--/v-->・別称 <!--v:names.alias-->177<!--/v-->・旧題名 <!--v:names.old_name-->749<!--/v-->・法令番号 <!--v:names.promulgation-->8,627<!--/v-->・施行予定の改正で変わる題名 <!--v:names.new_name-->14<!--/v-->）で決める。旧題名や改正後の題名で書いた引用もいまの法令として確かめ、そのことを注記する。題名が変わる予定の法令には、変わる日と新しい題名を添える。辞書の名前の直前に漢字が続く場合（「地方行政手続法」）は辞書の名前に読み替えず「該当なし」とする
2. 「所得税法第33条、第34条」「民法第901条第1項ただし書、第900条」のような並びは直前の引用の法令を引き継ぐ（直前の法令が分からなければ分からないことも引き継ぐ）。「同法施行令」「同施行令」「措置法施行規則」は前に出た（または頭に書いた略称の）法律の施行令・施行規則とする。法令名のない「第N条」は、同じ段落で直前に名前を書いた法令の条と**推定**し、その旨を示す。推定した法令にその条・項・号がなく、この文章で名前が出た他の法令（とその施行令・施行規則）のうちそれがあるものが一つだけなら、そちらとみなす（推定なので、条がなくても「存在しない」とは言い切らず ⚠ にする）。国税庁の資料などで使う略称（措法・措令・所法・所令・法法・消法・相法・通法・徴法 など）も読む。文章の中の略称の定め（「以下「法」という。」）、「同法」「同令」、「旧」「改正前の」（現行版では確かめない）、附則（確かめない）も読む
3. 条・項・号の有無を `data/structure.json.gz`（e-Gov スナップショット <!--v:snapshot-->2026-10-20<!--/v--> の <!--v:structure.laws-->8,981<!--/v--> 法令・<!--v:structure.articles-->243,501<!--/v--> 条の形、<!--v:structure.mb-->0.9MB<!--/v-->）で判定する
4. e-Gov API には 1 回の確認で最大 10 件だけ問い合わせる。スナップショットで「ない」と出たものを先に現行版で確かめ直し（スナップショット後の改正）、残りで「ある」ものの抜粋を取る。API が答えればそちらを優先し、答えなければスナップショットの判定を日付付きで返す

5. 通達・判例・条例・告示の引用（「所得税基本通達9-4-8」「最判平成5年3月11日」「東京都迷惑防止条例」など）は確かめず、「確かめていない引用」として数と一覧を返す（黙って飛ばすと、全部確かめたと読まれるため）

確かめるのは国の法令の条・項・号の実在だけで、引用した主張が条文に合っているかは判断しません。

2026-10-20・21 の測定（e-Gov 2026-09-27・2026-10-19 スナップショット）で test が警告した 6 件は、すべて租税特別措置法施行令・同施行規則の項・号でした。該当ページは「令和7年8月1日現在の法令・通達等に基づいて作成」で、スナップショットとのあいだの改正で項番号がずれたものと見ています（推定）。いまの内訳は `eval/results/verify_test.json` の `false_alarm_by_code`。古い資料の引用は `asof` で当時の版を指定して確かめてください。

**AI が書いた答えでの確認**: 上の質疑応答事例 50 問に AI（Claude Sonnet、このサーバーあり・なし）が書いた答え 100 件を使いました。問の id のハッシュで半分に分け、片方だけを見て直し（「同法施行令」の読み・同じ段落の法令の推定など）、もう片方で一度だけ測りました（<!--v:gate.date-->2026-10-21<!--/v-->）。引用 <!--v:gate.citations-->276<!--/v--> 件のうち <!--v:gate.checked-->257<!--/v--> 件（<!--v:gate.checked_pct-->93.1%<!--/v-->）を実在の判定に回せました（直す前は 85.8%）。法令名が決まらず判定しなかったものは <!--v:gate.no_name-->16<!--/v--> 件です。存在しないと出た <!--v:gate.missing-->3<!--/v--> 件は、改正前の号番号（法人税法第141条第4号）と、「同法」が文の上では別の法令を指してしまう書き方でした。推定した法令の条は、確認用の半分で手で見て 1 割弱が別の法令の条でした（推定の印を付けて返します。その後、条がある法令を選ぶよう直しました）。このサーバーを付けて答えさせた 150 件で、現行法にない条・項・号を挙げたものは「同法」「同条」が文の上では別の法令を指してしまう書き方だけで、ツールなしの 50 件では改正前の号番号が 1 件ありました（`eval/results/answer_eval.json`）。数値は `eval/results/gate_holdout.json`（`eval/gate_eval.mjs`）。

限界: 税務の資料だけで測っています。関係法令欄は整った書き方で、文の中に混ざった引用では法令名なし（ℹ）が増えます（回答本文で <!--v:test.C_info-->12.5%<!--/v-->）。誤りを入れる試験は条・項の有無をスナップショットで作っているので、確かめているのは「誤った引用を正しい法令・条に結び付けて判定に回せるか」です。

## データ源の利用条件（2026-10-19 確認）

- **e-Gov 法令API v2**: 時点指定（`asof`）は 2017-04-01 以降のみ（それより前は API がエラー 400044）。法令は著作権法第13条で権利の目的とならない。出典「e-Gov 法令検索（デジタル庁）」を付ける
- **国会会議録 API**: 手続不要。多重リクエスト禁止、取得し終えてから数秒空ける、1 回 100 件まで、短時間での大量アクセスは遠慮。発言の著作権は発言者にあるが、公開の政治上の演説・陳述は著作権法第40条で利用可（同一著作者のものの編集は除く）。結果は抜粋とリンクだけを返す
- 外部 API への負担を抑えるための決まりは [CONTRIBUTING.md](CONTRIBUTING.md)（回数制限は公開されていないが、2026-10-20 に毎秒約 4 件を 40 秒送ったところで一時的に止められた）

## データの更新

jlawcite は毎月 e-Gov から作り直されます（Hugging Face に日付のタグ）。このリポジトリの GitHub Actions（`.github/workflows/data-refresh.yml`）が毎日それを確かめ、新しければ `data/` の 3 ファイルを同じ検索DBから作り直し、テスト・評価（dev・test）・文書の数値（`scripts/render_docs.py`）を更新してコミットします。dev の評価が前回より 0.5 ポイント以上悪くなったときは反映しません。main への push で接続先も更新されます。いまのデータの出どころは `data/SOURCE.json`。

## 開発

```bash
npm install
npm test            # 単体テスト（実 API は呼ばない）
npm run build
LIVE=1 npx vitest run test/live   # 実 API に数件だけ問い合わせる（手で実行するときだけ）
node eval/verify_eval.mjs --gold <jlawcite の eval/v2/nta_gold.jsonl> --split dev   # 引用確認の評価（API は呼ばない）
python scripts/refresh_data.py --work work   # data/ を jlawcite の最新スナップショットに（3 ファイルを同じ検索DBから。pip install jlawcite が必要）
python scripts/render_docs.py                # README・DATA_LICENSE の数値と日付を data/・eval/results/ から埋める
python scripts/build_mcpb.py                 # Claude デスクトップの拡張（work/jp-law-mcp-<版>.mcpb）
```
